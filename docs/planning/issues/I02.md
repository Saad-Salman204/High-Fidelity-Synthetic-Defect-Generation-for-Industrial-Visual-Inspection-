# I02: Validate and lock the development and GPU environment

<!-- planning-id:I02 -->

## Background

Unverified CUDA/library combinations can consume the project deadline.

## Objective

Deliver: Version constraints and environment record.

## Scope

Create CPU development and GPU experiment setup instructions; pin a tested Python/PyTorch/torchvision/Diffusers/PEFT/Accelerate stack.

## Out of scope

Cloud deployment or distributed training. No work in this issue is implemented by the planning foundation.

## Implementation guidance

pyproject.toml and docs/planning/setup.md; record OS, Python, CUDA, driver, device memory and resolved package versions. Follow the architecture contracts and experiment protocol; do not silently change interfaces.

## Dependencies

None. Work may start only after prerequisite artifacts are reviewed.

## Deliverables

- Version constraints and environment record.
- Focused source/configuration/documentation changes and reproducible verification evidence.
- Versioned artifact metadata where the stage produces research outputs.

## Acceptance criteria

- [ ] Clean CPU environment imports package and passes foundation checks
- [ ] GPU allocation and tested version matrix recorded
- [ ] No large model downloads or GPU jobs in CI

## Testing requirements

Clean install, package imports and explicit unavailable-GPU behavior; real CUDA smoke check is separate from CI.

## Documentation requirements

Update the relevant module usage, contracts and version constraints and environment record. Link evidence and disclose unexecuted checks. Keep README status accurate.
